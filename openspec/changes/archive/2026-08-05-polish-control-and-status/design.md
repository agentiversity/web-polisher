## Context

Polishing is per-tab, driven by the popup's "Polish Page" button sending `apply-polish` to the content script. Each text node is its own LLM call (BATCH_SIZE 1), and the pipeline processes roots serially through a promise chain. The action icon is set via `browser.action.setIcon` from the background.

## Goals / Non-Goals

**Goals:**
- A start/pause/resume toggle for a running pass.
- Per-tab toolbar icon reflecting the lifecycle state.
- The popup closes immediately on trigger.

**Non-Goals:**
- Aborting the in-flight LLM call of the current node (pause takes effect between nodes).
- Per-tab icon persistence across browser restarts.

## Decisions

### 1. Toggle semantics in the content script
`apply-polish` becomes a state machine: idle/done → create a fresh pipeline and start; running → `pause()`; paused → `resume()`. The background icon is driven by `polisher-status` messages the pipeline emits via a status callback.

### 2. Pause gates the serial chain, not the network
The pipeline's `waitWhilePaused` also waits on a `paused` flag, so queued/observed roots stop between nodes. The in-flight node completes (its call is already sent). `resume()` clears the flag; queued and observed work (including off-screen roots via the IntersectionObserver) continues from where it stopped. The initial pass is routed through the same chain so it is pausable too.

### 3. Status model
`idle` (no pipeline / stopped), `running` (a batch in flight or roots/queued pending), `paused` (explicit pause), `done` (nothing left). `recomputeStatus()` runs after start, pause, resume, and each `processOne` completion. Content script reports `idle` on load so the icon resets on navigation.

### 4. Per-tab icons in the background
The background keeps `Map<tabId, status>`; content-script messages set it via `sender.tab.id`. `tabs.onActivated` re-applies the active tab's icon; `tabs.onUpdated` (loading) resets to idle. Icon files: gray idle (default), blue running, amber paused, green done (generated by `scripts/generate-icons.mjs`).

### 5. Popup closes immediately
The Polish button sends `apply-polish` fire-and-forget and calls `window.close()` immediately; polishing continues in the tab and the icon tracks it.

## Risks / Trade-offs

- **Pause isn't instantaneous** → it lands between per-node calls; acceptable since each call is a single text.
- **Status is fuzzy on dynamic pages** → "done" means all *currently known* content processed; new mutations flip it back to running.
- **Global vs per-tab icon** → per-tab via `setIcon({tabId})`; requires host permissions (already granted `*://*/*`).
