## Why

Phase 1 of the Text Polisher extension. Before any content detection, LLM transformation, or lazy loading matters, we must prove the extension can load in Firefox and safely replace page text **without breaking the framework-managed DOM** (React/Vue on Facebook & Reddit). DOM breakage is the existential risk — if text replacement corrupts pages, everything downstream is moot.

## What Changes

- Scaffold a Firefox MV3 extension project with **WXT** (TypeScript, Vite-based).
- Implement a **TreeWalker-based text-node replacer** that changes text content without destroying element references, event listeners, or framework fiber state.
- Add a **background service worker + content script skeleton** with a stub message-passing round-trip, establishing the CORS-safe architecture (all future LLM calls route through the background worker).
- Include a **spike** that verifies the TreeWalker approach on a real React-based page (Facebook/Reddit) before committing to it.

## Capabilities

### New Capabilities
- `text-replacement`: The extension installs and loads on Firefox and safely replaces page text without breaking page functionality or framework (React/Vue) state.

## Impact

- New WXT project files: `wxt.config.ts`, `package.json`, `entrypoints/background.ts`, `entrypoints/content.ts`, `entrypoints/options.html`.
- New dev dependencies: `wxt`, `typescript`, `@types/firefox-webext-browser`, `web-ext` (or equivalent).
- Manifest (auto-generated by WXT) with Firefox MV3 `browser_specific_settings`, `storage` + `activeTab` permissions, and `*://*/*` host/content-script matches.
- No LLM integration, content detection, or lazy loading in this phase (Phases 2–4).
